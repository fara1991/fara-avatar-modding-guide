::: point
- 上限は PC では Excellent が 0、Good が 1、Medium と Poor が 8
- PhysBone のコライダーとは別の項目
- Android と Quest では、コライダーは完全に無効と公式に書かれている
:::

コライダーの数（Physics Colliders）は、アバターにある Collider（Unity の物理の衝突の形を決める部品）の数です。PhysBone のコライダー（[PhysBone コライダーの数を減らす](/learn/optimize-physbone/physbone-colliders)）とは、別の項目です。

上限は、PC では Excellent が 0、Good が 1、Medium と Poor が 8 です（[VRChat の公式の表](https://creators.vrchat.com/avatars/avatar-performance-ranking-system)）。Android と iOS では、公式の Mobile Removed Components に入っていて、値は常にゼロと書かれています。

上限を超えると、次のランクに入ると書かれています（英語の原文の要約。[パフォーマンスランク](/learn/vrchat/performance-rank)）。表示の下限（Minimum Displayed Performance Rank）より下のランクになると、コライダーがすべて取り除かれます（原文: "All Physics Colliders removed"）。PC では、既定の表示の下限は Very Poor で、ほとんどのアバターは見えると書かれています。ただし、極端に最適化されていないアバターは、使えなくなる場合があると書かれています（英語の原文の要約です）。

VRChat の公式は英語の原文だけなので、ここでの引用は原文に訳を添えています。

## 減らす前に確かめること

- **SDK の「パフォーマンスの内訳」**: 「コライダーの数」で、今の値と上限を見ます。[パフォーマンスの内訳の見方](/learn/optimize-basics/read-the-breakdown) の例の画面では、1（上限 8）と表示されていました。
- **無効にしたものの扱い。** 公式は、「現在無効化されているものを含め、すべての GameObject とコンポーネントが、パフォーマンスランクに数えられる」（原文: "including those that are currently disabled"）と書いています（[Avatar Performance Ranking System（VRChat 公式）](https://creators.vrchat.com/avatars/avatar-performance-ranking-system)）。
- **PhysBone のコライダーと混同しないこと。** 公式の統計表の「PhysBones Colliders」は、"The number of PhysBone collider scripts on the avatar."（訳: アバターにある PhysBone のコライダーのスクリプトの数）で、別の項目です。
- **AAO を使うとき**: AAO の公式の基本的な使い方のページは、非破壊改変ツールを使う改変では、Control Panel のパフォーマンスランクはあてにならなくなると書いています。Play モードに入ったときのランクは、Actual Performance Window で確かめられます（[Avatar Optimizer（AAO）でできること・使い方](/learn/optimize-aao/avatar-optimizer)）。

## 減らし方の考え方

- 使っていないと確かめた Collider は、無効ではなく取り除きます（無効のものも数に入るため。公式の記述による）。
- PhysBone のコライダーは、AAO の Trace And Optimize で同じ設定のものを統合できます（PhysBone のコライダーの記事を参照: [PhysBone コライダーの数を減らす](/learn/optimize-physbone/physbone-colliders)）。

## ツール別の方法

### Avatar Optimizer（AAO） {.tool .tool-aao}

**何をするか**: Trace And Optimize の「PhysBone を最適化する」は、全く同じ設定の PhysBone Collider を 1 つに統合します（[Trace And Optimize（AAO 公式）](https://vpm.anatawa12.com/avatar-optimizer/ja/docs/reference/trace-and-optimize/)）。これは PhysBone のコライダーの統合です（[PhysBone コライダーの数を減らす](/learn/optimize-physbone/physbone-colliders) を参照）。

AAO の CHANGELOG には、Unity の Collider に関係する記録が 3 件あります。いずれも Fixed（不具合の修正）です。

| 版・日付 | 原文（抜粋） | 記録の中身（訳） |
|---|---|---|
| 1.5.2（2023-10-10） | `Avatar Standard Colliders can be removed` | コライダーが削除されることがあった不具合の修正 |
| 1.6.0（2023-11-27） | `Trigger Colliders can be disapper if you specify Transform instead of Collider instance.` | Collider のインスタンスではなく Transform を指定すると、Trigger Collider が消えることがあった不具合の修正（原文の綴りのまま） |
| 1.8.0（2024-11-30） | `Animation bindings for BoxCollider generated by VRCStation will be removed` | VRCStation が作る BoxCollider のアニメーションのバインドが消されていた不具合の修正。詳細には、Quest / Android に対応した GogoLoco などの飛行するアバターが壊れる可能性がある、とあります |

## 手順

1. SDK の「パフォーマンスの内訳」で「コライダーの数」を確かめます。PC の上限は、Excellent が 0、Good が 1、Medium と Poor が 8 です。Excellent の上限が 0 なので、1 つでもあると Excellent にはなりません（公式の表からの読み取りです）。
2. 変更の前に、プロジェクトのバックアップを取り、確かめたい動き（コライダーに関係する見た目や動き）を記録しておきます（**この記事の助言**{.lbl .lbl-adv}）。
3. 不要と確かめた Collider を取り除き、記録と比べます。
4. もう一度 SDK の「パフォーマンスの内訳」を開き、「コライダーの数」を確かめます。

## 注意・うまくいかないとき

::: warning
- **モバイル（Android と iOS）**: 公式の Mobile Removed Components は、"The following components are disabled on mobile devices since they can never appear on avatars:"（訳: 次のコンポーネントは、アバターに表示されることがないため、モバイルの端末では無効になります）と書き、その一覧に Physics Colliders が入っています。公式は、この値は "they are always zero"（いつもゼロ）と書いています。
- **Android と Quest**: 公式の Quest Content Limitations は、"Rigidbodies, colliders, and joints are disabled completely for avatars on Android and Quest."（訳: Android と Quest では、アバターの Rigidbody・コライダー・ジョイントは完全に無効になります）と書いています（[Quest Content Limitations（VRChat 公式）](https://docs.vrchat.com/docs/quest-content-limitations)）。
- **数値は変わることがあります**: 公式は、Optimization Tips の推奨の数値や上限は、いつでも変わる可能性があると書いています（原文: "Any recommended numbers or limits in this document are subject to change at any time."）。
:::
