VRChat のアバターを軽くするツールは何種類もあり、ツールごとに減らせる項目が違います。この記事では、よく使われる 5 つのツールについて、何をするか、どの項目を減らせるかを整理します。

略称は、MA（Modular Avatar）、TTT（TexTransTool）、MMS（Meshia Mesh Simplification）、AAO（Avatar Optimizer）です。lilAvatarUtils は、そのまま書きます。

表の項目名は、画面に表示される名前に合わせています。PhysBone（髪や服を揺らす仕組み）や、コンストレイント（ある物の位置や向きを、別の物に合わせる仕組み）などの項目の上限の値は、[パフォーマンスランク](/learn/vrchat/performance-rank) にあります。

各ツールのコンポーネントを追加するメニュー名は、公式ページに書かれていないものが多いため、この記事ではコンポーネント名だけを書いています。

::: warning
ツールは更新されることがあります。この記事は **2026 年 11 月 5 日** に公式ページを確かめて書きました。版が変わっているときは、公式ページの最新の情報を優先してください。
:::

## 1. Modular Avatar（MA）

Modular Avatar は、衣装などを本体に組み立てるためのツール群です。衣装のボーンを本体に統合する Merge Armature や、アニメーターを統合する Merge Animator などがあります。公式は「非破壊」のツール群だと説明しています。非破壊とは、元のデータを書き換えずに、プレイモードやアップロードのときに処理する、という意味です。

- **確認した版**: 1.18.7（2026 年 9 月 1 日）。テスト版は 1.19.0-beta.0 です。
- **入れ方**:
  - ALCOM: 「パッケージ管理」から「VPMリポジトリを追加」を選び、リポジトリ `https://vpm.nadena.dev/vpm.json` を追加します。プロジェクトの「管理」で Modular Avatar の「+」を押して、「適用」します。
  - VCC: 公式ページのリンクからリポジトリを追加し、manage project で「+」を押します。
  - テスト版は、公式が ALCOM から入れるよう案内しています。VCC では依存関係の解決にバグがあると書かれています。
- **ライセンス**: MIT License。ただし `Editor/images` の画像は MIT の対象外で、公式パッケージの一部としてのみ再配布できます。
- **対応**: Unity 2022.3（main ブランチ 1.19.0-beta.0 の package.json の値）。1.18.x の値は確認できませんでした。VRChat SDK の対応版は、公式には書かれていません。NDMF（ビルド時の処理を動かす仕組み）が必要です。
- **公式ページ**: https://modular-avatar.nadena.dev/ja （GitHub: https://github.com/bdunderscore/modular-avatar ）
- **減らせる主な項目**: ボーン（Merge Armature）、アニメーター（Merge Animator）、三角ポリゴン（Mesh Cutter・条件つき）
- **注意**:
  - Mesh Cutter を常にオンにしたとき、指定した部分のポリゴンが削除されます。部位が見えなくなるので、見た目も変わります。時々オフにして非表示にする使い方では、コンストレイントが生成され、ランクが上がることがあります。
  - Merge Animator の「付属アニメーターを削除」をオンにすると、同じオブジェクトの Animator が除外されます。同じレイヤーの種類で置き換えの設定が複数あるとエラーになります。
  - Merge Motion（Blend Tree 版）は、時間で変わるアニメーションには向きません。
  - 衣装を組み込む手順は、[Modular Avatar で衣装を着せる](/learn/unity/modular-avatar-outfit) を見てください。

## 2. TexTransTool（TTT）

TexTransTool は、テクスチャを元のまま残して、加工するツールです。公式は「非破壊テクスチャ改変ツール」と説明しています。デカール（テクスチャに画像を貼る機能）、アトラス化（必要な部分だけを集めた 1 枚のテクスチャを作り、VRAM＝グラフィックボードのメモリーを減らす機能）、PSD の取り込みなどがあります。

- **確認した版**: v1.0.2（GitHub の最新版）。公開日は「26 Jun」と表示され、年は確認できませんでした。
- **入れ方**: VCC か ALCOM から、パッケージ `net.rs64.tex-trans-tool` を入れます。VPM リポジトリは `https://vpm.rs64.net/vpm.json` です。公式サイトの「Download-VPM」ボタンからも追加できます。
- **ライセンス**: 未確認です。LICENSE.md の本文を確認できませんでした。
- **対応**: Unity 2022.3（VPM の情報）。VRChat SDK の対応版は、公式には書かれていません。アバターの改変に使うときは、NDMF が必須です。公式は、同時に入れることを勧めています。
- **公式ページ**: https://ttt.rs64.net （チュートリアル: https://ttt.rs64.net/docs/Tutorial ）
- **減らせる主な項目**: テクスチャメモリー（条件つき）
- **注意**:
  - 適用はビルドのときに行われます。Manual Bake Avatar か Unity の Play で確かめてから、アップロードしてください。プレビューの状態のままアップロードすると、処理が中断されると書かれています。
  - アトラス化の出力をそのまま使うと、VRAM が増える場合があると書かれています。
  - AtlasTexture はマテリアルを結合しますが、マテリアルスロットは結合しません。スロットを減らすには、AAO の併用が案内されています。
  - Quest 向けに結合すると、見た目は保てません。
  - TextureConfigurator は実験的な機能で、仕様が変わる、または削除されることがあります。
  - 元に戻す（Revert）方法は、確認できませんでした。

## 3. lilAvatarUtils

lilAvatarUtils は、アバターの改変を助けるツールです。公式は「Utilities for avatar modification.」と書き、日本語のサイトでは「アバター改変補助ツール」と紹介しています。テクスチャ・マテリアル・レンダラー・PhysBone・PBコライダーの一覧を見て、編集できます。ライティングの確認や、不要なものの整理もできます。

- **確認した版**: 2.1.2（2025 年 8 月 11 日）。
- **入れ方**: VCC は、公式サイトの「Add to VCC」ボタンで VPM リポジトリ `https://lilxyzw.github.io/vpm-repos/vpm.json` を追加します。ALCOM での入れ方は、公式では確認できませんでした。
- **ライセンス**: MIT License。
- **対応**: Unity 2022.3（VPM の情報）。VRChat SDK の対応版は、公式では確認できませんでした。
- **メニュー**: Unity の `Tools/lilAvatarUtils` から開きます（公式の 2.0.0 以降の表記）。
- **公式ページ**: https://lilxyzw.github.io/lilAvatarUtils/ja_JP/
- **減らせる主な項目**: テクスチャメモリー（解像度・ミップマップ・圧縮）。PhysBone やコライダーは、見つけるための用途で、減らす操作は書かれていません。
- **注意**:
  - 公式のページには、元のアセットを書き換えるかどうかが書かれていません。「適用」ボタンで変更をまとめて反映するので、作業の前にプロジェクトのバックアップを取るのが安全です。
  - マテリアルのレンダーキューを下げすぎると、ほかのマテリアルが消えやすくなると書かれています。
  - Bounds の設定を誤ると、表示が消えたり、ライトが暗くなったりすることがあります。

## 4. Meshia Mesh Simplification（MMS）

Meshia Mesh Simplification は、メッシュの三角ポリゴンの数を減らす（簡略化する）ツールです。アバター向けの「Meshia Cascading Avatar Mesh Simplifier」を使うと、アバター全体の目標を決めて、各メッシュに数を配分できます。目標は、性能ランクを選ぶ形です。

- **確認した版**: 3.3.1（2026 年 11 月 4 日に公開）。
- **入れ方**: VCC に作者の VPM リポジトリ `https://ramtype0.github.io/VpmRepository/` を追加し、Manage Project から Manage Packages を開いて Meshia Mesh Simplification を追加します。ALCOM での入れ方は、公式ドキュメントに書かれていません。
- **ライセンス**: MIT License（`Copyright (c) 2025 Ram.Type-0`）。
- **対応**: Unity 2022.3（パッケージの情報）。パッケージには `vrchatVersion: 2022.1.1` と書かれていますが、その意味は公式には説明されていません。
- **依存**: アバター向けの機能には Modular Avatar が必要です。ワールド向けの機能には NDMF が必要です。
- **公式ページ**: https://ramtype0.github.io/Meshia.MeshSimplification/ （README: https://github.com/RamType0/Meshia.MeshSimplification ）
- **減らせる主な項目**: 三角ポリゴンの数（目標の数を指定）
- **注意**:
  - 目標を下げすぎると、形が崩れやすくなります。どの数値から崩れるかは、公式ドキュメントに数値で書かれていません。
  - 指先に穴があいたら、Preserve Border Edges を有効にすると公式が案内しています。
  - 公式ドキュメントには、非破壊かどうかは書かれていません。作業の前にバックアップを取るのが安全です。
  - Avatar Optimizer との連携は、公式ドキュメントに書かれていません。

## 5. Avatar Optimizer（AAO）

Avatar Optimizer は、アップロードのとき（ビルドのとき）や、Play モードに入るときに、アバターを自動で軽くする非破壊のツール群です。元のアバターは変わらず、ビルドのときの一時的なコピーにだけ働きます。公式は、見た目や動きを変えずに性能を上げることを目標にしていて、意図しない変化は不具合として扱うと、FAQ に書いています。

- **確認した版**: 1.9.21（2026 年 10 月 30 日）。
- **入れ方**: 公式は ALCOM から入れることを推奨しています。VCC では正しく動かないことがあるためです。ALCOM で VPM リポジトリ `https://vpm.anatawa12.com/vpm.json` を追加してから、`com.anatawa12.avatar-optimizer` を追加します。UnityPackage や vrc-get からの入れ方も書かれています。
- **ライセンス**: MIT License。
- **対応**: Unity 2022.3（VPM の情報）。VRChat SDK は、`com.vrchat.avatars` の 3.7.0 以上 3.11.0 未満と書かれています（VPM の情報）。NDMF が必要です。
- **公式ページ**: https://vpm.anatawa12.com/avatar-optimizer/ja/ （GitHub: https://github.com/anatawa12/AvatarOptimizer ）
- **減らせる主な項目**: テクスチャメモリー、三角ポリゴンの数（隠れた部分）、スキンドメッシュの数、マテリアルスロットの数、PHYSBONE のコンポーネント・トランスフォーム・コライダーの数、ボーンの数（自動と手動の両方で減らせます）
- **注意**:
  - Trace And Optimize は、アバターのルート（VRC Avatar Descriptor のある GameObject）に付けます。ルート以外に付けると、Inspector にエラーが出て、動きません。
  - Merge Skinned Mesh で統合すると、メッシュを個別にアニメーションでオン・オフできなくなります。
  - マテリアルをアニメーションで切り替えるアバターでは、マテリアルの統合と衝突することがあります。公式の FAQ に、既知の不具合として書かれています。
  - 公式ドキュメントでは、Control Panel の Performance Rank は、非破壊ツールでは信頼できないとされています。Play モードで確かめる方法が案内されています。
  - 「使われていないObjectを自動的に削除する」の対象は、公式に詳しく書かれていない部分があります。

::: tip
TTT の AtlasTexture は、マテリアルスロットを減らさないと明記されています。そのうえで、スロットを減らすには AAO との併用が案内されています。このように、ツールを組み合わせて減らす方法もあります。
:::

### 記号の意味

- **○ 減らせる**: そのツールに、その項目を減らす操作が書かれています。
- **△ 条件つき**: 減る場合もありますが、条件があります。増える場合もあります。下の表の注を見てください。
- **分析のみ**: 数を表示したり一覧にしたりできますが、減らす操作は書かれていません。
- **× 減らせない**: 公式の資料に、このツールでは減らせない、または、その機能がないと書かれています。
- **？ 記載なし**: 公式の資料に、その項目を減らす機能が書かれていません。減らせないと決めつけてはいません。
- **？ 未確認**: 関係する記載はありますが、効果が分からない、または確かめられませんでした。

### 表の注

- **テクスチャメモリー**: TTT は、アトラス化・解像度・圧縮で減らせる場合があります。ただし、アトラスの出力をそのまま使うと、増えることがあります。lilAvatarUtils は、解像度・ミップマップ・圧縮で減らします。AAO は、対応しているシェーダーのマテリアルについて、テクスチャのサイズを自動で小さくします。
- **三角ポリゴンの数**: MA の Mesh Cutter は、部位を削除します。部位が見えなくなるので、見た目が変わります。MMS は、目標の数を指定します。AAO は、隠れた部分を、マスク・箱・UV タイル・BlendShape で削除します。見える部分を消すと、見た目が変わります。lilAvatarUtils は、数を表示するだけです。
- **範囲（BOUNDS）**: MA の Bounds 設定は、設定モードを選んだときにだけ効きます。ランクへの効果の大きさは、確かめられませんでした。lilAvatarUtils は、一覧で確認するだけです。編集できるかは確かめられませんでした。
- **スキンドメッシュの数・基本メッシュの数**: AAO の Merge Skinned Mesh は、スキンドメッシュを 1 つにまとめます。基本メッシュ（ボーンで動かないメッシュ）は、Merge Skinned Mesh の「メッシュレンダラー」の設定で、手動でまとめられます。自動の対象になるかは、確かめられませんでした。
- **マテリアルスロットの数**: TTT の AtlasTexture は、マテリアルを結合しますが、マテリアルスロットは結合しません。
- **PHYSBONE の項目（MA）**: MA の Replace Object は、置き換え先の構成によって数が変わります。数を減らす機能は書かれていません。
- **PHYSBONE の項目（AAO）**: AAO の Merge PhysBone は、まとめるたびにトランスフォームの数が 1 つ増えます（公式ページの記載）。
- **PHYSBONE コライダーの数（MA）**: PhysBone Blocker は影響を止めるだけで、コライダーは減らしません。Global Collider は、コライダーを増やす機能です。
- **コライダーの数（lilAvatarUtils）**: 分析できるのは PhysBone 用のコライダーだけです。通常の Collider を含むかは、確かめられませんでした。
- **コンストレイントの数**: MA の Convert Constraints は、事前に変換すると性能が大きく上がると公式が書いています（数値は書かれていません）。一方、Merge Armature や Mesh Cutter は、コンストレイントを増やす場合があります。
- **アニメーターの数**: MA の Merge Animator は、「付属アニメーターを削除」をオンにしたときに減らせます。AAO の「アニメーターの最適化」は、レイヤーを整理するもので、Animator の数は書かれていません。
- **ボーンの数**: MA の Merge Armature は、名前が一致するボーンを統合先にまとめます。名前が合わないと、新しいボーンが増えます。AAO は、使われていないObjectを削除します。
- **ライトの数（lilAvatarUtils）**: ライティングのタブは、見え方を確かめるためのものです。ライトを一覧にしたり、削除したりする機能はありません。
- **レイキャストの数（MA）**: Parameters の VRCRaycast 対応は、パラメーターの型としての対応です。数を減らす機能ではありません。

## ツールだけでは減らせない項目の考え方

- 表で「？」や「×」になっている項目は、どのツールでも直接は減らせないか、公式の資料で確かめられなかった項目です。
- ツールで減らせない項目は、Unity の標準の操作で減らします。たとえば、使わないコンポーネントを取り除く、使わないオブジェクトを消す、といった方法です。
- まず、今どの項目が重いのかを見ることが大事です。Builder でランクを確かめ、いちばん悪い項目から減らします（[パフォーマンスランク](/learn/vrchat/performance-rank)）。
- AAO の公式ドキュメントは、Control Panel の Performance Rank は非破壊ツールでは信頼できないとして、Play モードで確かめる方法を案内しています。AAO を使ったあとのランクは、この方法で確かめてください。
- 減らす手順の例は、[アバターを軽くする](/learn/vrchat/optimization) にまとめています。
- ツールを入れたあとは、Build & Test で見た目と動きが変わっていないかを確かめてください。
- 複数のツールを併用するとき、順序や衝突について公式に書かれていない組み合わせがあります（MA と AAO など）。想定どおりに動くか、実際に確かめてください。
