スケールを適用していない

Blender書き出しモデリング Discord より
症状
ソリッド化の厚みやベベルの幅が軸ごとに違う。Unity に入れると大きさが 100 倍・0.01 倍になる。
原因
オブジェクトモードで拡大縮小すると、メッシュではなくオブジェクトの「スケール」の値が変わる。モディファイアーや書き出しはその値の影響を受ける。
直し方
  • オブジェクトを選んで Ctrl+A > スケール（書き出し前は 全トランスフォーム）
  • サイドバー（N）でスケールが 1.000 になっていることを確かめる
  • アーマチュアで動かしているメッシュは、アーマチュアと一緒に適用する
詳しく

アバターと服を結合（Ctrl+J）したら大きさが変わった

アーマチュアやメッシュのスケールが 1 になっていないと、結合時に片方の大きさが変わります。結合前にそれぞれ Ctrl+A → 全トランスフォームを適用してスケールを 1 にします。

  1. N でサイドバーを開き、アバターと服それぞれのアーマチュア（とメッシュ）のスケールが 1 か確認します。
  2. 1 でないものを選択し、Ctrl+A → 全トランスフォーム を適用します。見た目はそのままでスケールが 1 になります。
  3. 両方が 1 になった状態で結合します。
  • メッシュ結合で「衣装が素体に対して大きく表示される」場合も同じく適用漏れが原因です。
  • FBX の読み込み直後はアーマチュアに 0.01 などのスケールが付いていることがあります。

Unity でマテリアルがピンク（マゼンタ）になる

Unityマテリアル Discord より
症状
アバターや衣装を入れたら、表面が真っピンクになる。
原因
マテリアルが使うシェーダーがプロジェクトに無い。衣装が lilToon などを前提にしているのに、プロジェクトに入っていないことが多い。
直し方
  • 衣装の説明で、必要なシェーダー（lilToon など）とバージョンを確かめる
  • VCC / ALCOM のパッケージ、または配布元の unitypackage でシェーダーを入れる
  • 入れたあとも直らなければ、マテリアルの Inspector でシェーダーを選び直す
詳しく

アバターや衣装がピンク色（マゼンタ）で表示されるのはなぜですか？

マテリアルが参照しているシェーダーがプロジェクトに入っていないか、読み込みに失敗しています。作者が指定するシェーダーを導入し、直らなければシェーダーを Reimport します。

  • ピンク色は「シェーダーが見つからない／コンパイルできない」状態です。
  • 対処
    1. アバター・衣装の説明書で指定されているシェーダー（lilToon、UTS2、Poiyomi など）を導入します。
    2. 導入後も直らない場合は、該当シェーダーのフォルダを右クリック → Reimport を試します。
    3. それでも駄目ならアバターのアセットを一度削除し、シェーダー → アバターの順にインポートし直します。
  • マテリアルを選択し、Inspector 上部の Shader 欄が正しいシェーダーになっているかも確認します。
  • VRM（MToon）向けの書き出しで MToon 以外のシェーダーを使うと、Standard シェーダー扱いになり金属のような見た目になることがあります（VRM の MToon 変換）。

体が服を突き抜ける

BlenderウェイトUnity Discord より
症状
腕を曲げたりしゃがんだりすると、体が服の外に出てくる。
原因
服と体のウェイトが合っていない、または服が体に近すぎる。
直し方
  • 服のウェイトを体から転送し直す（データ転送）
  • 服を少しだけ外に膨らませる（編集モードで Alt+S）
  • 服で隠れる部分の体は、シェイプキーで縮めるか、服の下の体のメッシュを消す
詳しく

衣装から肌が突き抜ける（貫通する）ときの対策

主な対策は、①見えない素体メッシュを消す、②素体を細くするシェイプキーを作る、③衣装を少し膨らませる、④素体と衣装の頂点数・位置を揃える、⑤ウェイトを揃える、です。関節まわりが特に貫通しやすいです。

原因

  • 素体と衣装の頂点の数・位置が違うと、曲げたときにどちらかがはみ出します（頂点が少ない側が内側の頂点を突き抜けやすい）。
  • 素体と衣装でウェイトや関節位置が違う。

対策

  1. 素体メッシュを消す: 衣装で隠れる部分なら一番確実です。メッシュが分かれていれば軽量化にもなります。
  2. 素体を細くするシェイプキー: 消すのが不安なら、肩・肘・膝・脚の付け根など関節まわりや脇の下を細くするシェイプキーを作り、衣装に合わせて値を入れます。Unity 側で調整できるので、非対応衣装も Unity だけで済む場合があります。
  3. 衣装を少し膨らませる: 貫通箇所だけ外側に出します。
  4. 頂点数・位置を揃える: 貫通箇所を細分化してポリゴンを増やす、など。
  5. ウェイトを揃える: 素体からウェイトを転送します（ウェイト転送）。体のウェイトが入り組んだ箇所（Spine と Chest の境目など）は、捻ると貫通しやすくなります。
  6. 素体に衣装と同じ色を塗る: テクスチャ側でごまかす方法もあります。
  • Unity だけで行う場合は、体を細くするシェイプキーを自動作成するエディタ拡張（DietShaper など）も使えます。
  • 何枚も重なった衣装で肌が見えない部分は、貫通防止用のシェイプキーでまとめて絞るのが現実的です。

Unity で服が 90° 回っている・寝ている

BlenderUnity書き出し Discord より
症状
FBX を Unity に置くと、横倒しになっている。Rotation に -90 などの値が入っている。
原因
Blender（Z が上）と Unity（Y が上）の軸の違いが、オブジェクトの回転として残っている。
直し方
  • 書き出す前に Ctrl+A > 全トランスフォーム を適用する
  • FBX 書き出しの「トランスフォーム」の前方 -Z・上 Y（既定値）を変えていないか確かめる（衣装の配布元の推奨設定があればそれに従う）
  • 同じ欄の「トランスフォームを適用」は実験的な機能で、アーマチュアでは正しく動かないことがわかっているので、アバターでは使わない
詳しく

Blender で合わせた服やアクセサリーが Unity では傾く・向きが変わる

Blender（Z 上）と Unity（Y 上）の座標系の違いで、FBX 読み込み後に Rotation X が -89.98 のようなわずかにずれた値になることがあります。Blender 側で回転を整えて書き出し、Unity で Rotation が (0, 0, 0) になるようにします。

  • 通常は FBX エクスポーター／インポーターが自動で変換するので、普段は気にしなくて大丈夫です。おかしくなったときだけ対処します（揺れものの動きがおかしくなる形で表れることもあります）。
  • シェイプキーのないメッシュの場合（概要）
    1. Shift+S → カーソルをワールド原点へ。ピボットポイント（.）を 3D カーソルにします。
    2. 全オブジェクトを X 軸に -90° 回転 → 回転を適用 → X 軸に +90° 回転（適用しない）、の手順で、Blender 上の Rotation X が 90 の状態にします。
    3. FBX を書き出し、Unity で Rig の向きや Rotation が (0, 0, 0) になっているか確認します。
  • シェイプキーのあるメッシュの場合: メッシュを固定したまま座標軸だけを回転させる方法を使います（オブジェクトモードで実行）。
  • 詳しい手順は外部記事「BlenderとUnityの座標系の違いを治す」を参照してください。
  • Maya 製のアバターなどは、Blender を通すとスケールが 100 倍になる・回転値が残るなどの差が出ることがあります。

シェイプキーがあるとモディファイアーを適用できない

Blenderリギングモデリング Discord より
症状
モディファイアーの「適用」で「Modifier cannot be applied to a mesh with shape keys」と出る。
原因
Blender は、シェイプキーを持つメッシュへのモディファイアーの適用を（そのままでは）できない。
直し方
  • シェイプキーを作る前に、ミラーなどのモディファイアーを適用しておく（作業の順番で避ける）
  • すでにシェイプキーがある場合は、シェイプキーを保ったまま適用するアドオンを使う。FBX 書き出しの「モディファイアーを適用」をオンにすると、シェイプキーが書き出されなくなるので代わりにはならない
詳しく

シェイプキーがあるメッシュにモディファイアーを適用できない

Blender の仕様で、シェイプキーを持つメッシュには通常モディファイアーを適用できません。シェイプキーを Basis に反映して削除するか、シェイプキーを保ったまま適用できるアドオンを使います。ウェイトだけならウェイトペイントモードの「ウェイトを転送」で適用不要にできます。

  • 選択肢
    1. シェイプキーを使っていない → 削除してから適用します。
    2. シェイプキーで形を調整していた → 必要な形を Basis に反映してから全シェイプキーを削除し、適用します。
    3. シェイプキーを残したい → シェイプキー付きメッシュにモディファイアーを適用できるアドオン（ApplyModifier など）を使います。
  • ウェイト転送が目的なら: モディファイアーを使わず、ウェイトペイントモードの ウェイト > ウェイトを転送（Transfer Weights） を使うと、シェイプキーがあってもそのまま転送できます。
  • Armature モディファイアーは 適用せずに残しておく ものです（服が動かない）。

Unity のバージョンが違うと言われる

UnityVRChat Discord より
症状
VCC / ALCOM でプロジェクトを開くと、Unity のバージョンが違う・見つからないと表示される。SDK が入らない。
原因
VRChat が対応している Unity のバージョン（2026 年 10 月時点は 2022.3.22f1）以外で開いている。
直し方
  • VCC / ALCOM が案内する Unity のバージョンを、Unity Hub から入れる
  • 新しいプロジェクトは VCC / ALCOM から作る（Unity Hub から直接作らない）
詳しく

VRChat から Unity のバージョンを上げるよう言われたら

VRChat が指定するパッチバージョンに上げ、合わせて VRChat SDK も更新します。同じマイナー系列（例: 2022.3.x）内の更新ならプロジェクトはそのまま移行できることが多いです。ただし、事前にバックアップを取ります。

  • VCC / ALCOM や Unity Hub から、指定されたバージョンの Unity をインストールし、プロジェクトのバージョンを切り替えます。
  • Unity を上げたら VRChat SDK も最新に更新します。
  • 当時の事例: 2022.3.6f1 → 2022.3.22f1 への移行はそのまま開け（初回起動は時間がかかる）、FBX のフレームレートに関する警告が出た程度でアップロードできました。
  • 大きくバージョンが変わる場合（メジャー更新）は、新しいプロジェクトを作って移行する方が安全なこともあります。
  • VRChat が指定するより新しい Unity（Unity 6 など）でアップロードしたものは、VRChat で読み込めません。VRChat の案内が出るまでは上げないでください。

パフォーマンスランクが Very Poor になる

VRChatモデリング Discord より
症状
Builder でアバターのランクが Very Poor になり、ほかの人から見えにくくなる。
原因
三角形の数・マテリアル数・Skinned Mesh の数・PhysBone の数などのどれかが上限を超えている。いちばん悪い項目がランクになる。
直し方

詳しく

パフォーマンスランクが Very Poor になるのは普通ですか？

最近の販売アバターは衣装切り替えなどを含むと Very Poor になることが多いです。ポリゴン数・メッシュ数・マテリアルスロット数・PhysBone 数などで決まるので、人の多い場所用に軽い版を用意すると親切です。

  • ランクは複数の項目のうち最も悪い項目で決まります（ポリゴン数、Skinned Mesh 数、マテリアルスロット数、PhysBone のコンポーネント数・Transform 数・コライダー数など）。

髪の PhysBone をまとめてコンポーネント数を減らす

前髪・横髪・後ろ髪ごとに空のオブジェクトを作り、各ボーンのルートをその子にまとめて、空オブジェクトに PhysBone を 1 つずつ付けると、コンポーネント数を大幅に減らせます。

詳しく
  1. 髪のルートボーン（Head など）の下に、前髪・横髪・後ろ髪用の空の GameObject を作ります。

細い紐やスカートのボーンが貫通するときは、コライダーを V 字に 2 つ置く

詳しく
  • コライダーの線（境界）は足とボーンの間に来るように置くのが基本です。
  • 絶対に貫通させたくない場合は、大きめのコライダーを 2 つ使って V 字の谷を作り、ボーンをその谷に乗せる配置にします（内側コライダーの代わり）。
  • コライダーが増えると負荷も増えます。VRChat の PhysBone には Inside タイプのコライダーもあるので、まずそちらで足りるか検討します。
  • VRM（SpringBone）には Inside コライダーがないため、この方法が特に有効です。
