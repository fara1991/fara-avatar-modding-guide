改変は Unity と Blender のどちらから始めればよいですか？

BlenderUnityVRChatマテリアル Discord より

髪色の変更や対応衣装の着せ替えなど、基本的な改変は Unity と画像編集ソフトだけでできます。衣装が肌に埋まる・体形が合わないなど、メッシュそのものを直す必要が出たら Blender を使います。

詳しく
  • まずは Unity から 始めるのがおすすめです。アバターのアップロード、対応衣装の着せ替え、表情・メニュー設定はすべて Unity で行います。
  • 髪や服の色を変えるだけなら Blender は不要 です。テクスチャ（画像）を画像編集ソフトで編集するか、lilToon の色調補正を使います。
    • 画像編集ソフトの例: GIMP（無料）、CLIP STUDIO PAINT、Photoshop。色変更程度なら GIMP でも十分です。
  • Blender が必要になる場面 の目安
    • 衣装を着せたら肌が衣装を突き抜ける（貫通する）、衣装が体に埋まる
    • 非対応衣装を着せたい、体形（胸・脚など）に合わせてメッシュを変形したい
    • 不要なメッシュの削除、ボーンやウェイトの修正、シェイプキーの追加
  • Unity だけでメッシュを触れるエディタ拡張もありますが、細かい調整は Blender の方が融通が利きます。
  • 現行では対応衣装の着せ替えは Modular Avatar（MA）の「Setup Outfit」で Blender なしに行うのが一般的です。

購入したアバターを VRChat にアップロードする基本の流れ

UnityVRChat Discord より

VCC（VRChat Creator Companion）でプロジェクトを作り、アバターの unitypackage を入れて SDK の Builder タブからアップロードします。当時の手順（Unity 2019 / Game ビューで名前を入れる）とは画面が変わっています。

詳しく

現行の流れ（VRChat SDK3 / VCC）

  1. VCC（または ALCOM）で、テンプレート Avatar のプロジェクトを作成します。Unity は VRChat が指定するバージョン（2026 年 10 月時点は 2022.3.22f1）を使います。
  2. アバター作者が指定するシェーダー（lilToon など）を先に導入し、その後アバター本体の .unitypackage をインポートします。
  3. Project ウィンドウからアバターの Prefab を Hierarchy にドラッグします（FBX ではなく Prefab を使います）。
  4. メニューの VRChat SDK > Show Control Panel → Authentication でログインし、Builder タブでエラー・警告を確認します。
  5. 名前・公開範囲（Visibility）・サムネイルなどを設定し、Build & Test で確かめてから、権利確認にチェックを入れて Build & Publish を押します。
  • アップロードできるのは、トラストランクが New User 以上のアカウントです（Visitor でも Build & Test は使えます）。

よくあるつまずき

  • 全体がピンク色 → シェーダー未導入です（ピンク色になる）。
  • Unity のバージョン違い → VCC が案内するバージョンを使います。
  • 揺れものが動かない → 当時は有料アセット DynamicBone が必要でしたが、現在は VRChat 標準の PhysBone を使います。

当時（2022 年頃）との違い

  • 当時は Unity 2019.4.31f1 を手動で入れ、SDK の「Build & Publish for Windows」を押したあと Game ビューでアバター名を入力して Upload していました。現在は Builder タブ内で完結します。
  • DynamicBone を持っていない場合は Missing Remover で欠けたスクリプトを消す手順がありましたが、PhysBone 対応アバターでは不要です。

Blender から書き出した FBX を Unity に入れたらテクスチャ・マテリアルがおかしい

BlenderUnityマテリアル衣装 Discord より

Blender で付けたマテリアル情報は Unity では実質使えません。元のアバター・衣装の unitypackage に入っている Unity 用マテリアルを、FBX の Materials タブで割り当て直します。

詳しく
  • 前提: Blender のマテリアル／テクスチャ設定は Unity 側ではほぼ使えないので、Unity 側でマテリアルを設定し直す 必要があります。
  • 手順
    1. 元のアバターと衣装の .unitypackage をインポートしておきます（素体の FBX から抜き出したマテリアルではなく、パッケージに付属する Unity 用マテリアルを使います）。
    2. Project で書き出した FBX を選択 → Inspector の Materials タブを開きます。
    3. Remapped Materials の各スロットに元のマテリアルをドラッグして Apply します。
    • もしくは Extract Materials で FBX 内のマテリアルを取り出し、手動で全部設定します。
  • Blender でマテリアル名を変えていなければ、元のマテリアルと同じ名前のスロットに割り当てれば元通りになります。
  • 割り当てたら輪郭線（アウトライン）が太くなった → Blender を通すと輪郭線が太くなる を参照してください。
  • 衣装とアバターで別々にマテリアルがあるので、どちらも入れ忘れないようにします。

Unity の Project / Hierarchy / Inspector / Prefab / 親子関係とは？

Unity Discord より

Project はアセット置き場、Hierarchy はシーンに置いたオブジェクトの一覧、Inspector は選択したものの設定欄です。オブジェクトを別のオブジェクトの中に入れることを「子にする（親子関係）」と呼びます。

詳しく
  • Project: プロジェクト内のファイル（Prefab、FBX、マテリアル、テクスチャ）。Unity 上のエクスプローラーのようなものです。インポート後のファイル操作は基本的にここで行い、Windows のエクスプローラーで直接いじらないようにします。
  • Hierarchy: シーンに置いたオブジェクトの一覧。Project から Prefab や FBX をドラッグして置きます。
  • Inspector: 選択中のオブジェクトやファイルの設定。右上の鍵アイコンで表示をロックすると、別のものをドラッグするときに便利です。
  • Prefab: オブジェクト構成を保存したもの。アバターは FBX ではなく Prefab を Hierarchy に置きます。
  • 親子関係（入れ子）: Hierarchy で A を B の上にドラッグすると、A が B の子になり B に追従して動きます。
  • Add Component: Inspector 最下部のボタン。検索欄に名前を入力してコンポーネント（スクリプト）を追加します。
  • Unpack Prefab Completely: Prefab とのリンクを切ります。元データを壊さないよう、改変前に Prefab Variant を作る方法もあります。
  • マテリアルはシーン上のメッシュに直接ドラッグ＆ドロップしても割り当てられます。

アップロード時に「Error saving blueprint」と出る

UnityVRChat Discord より

アバターに付いている Pipeline Manager の Blueprint ID が自分のアカウントのものではありません。Detach で ID を空にしてから新規アップロードします。

詳しく
  • アバターのルートを選択 → Inspector の VRC Avatar Descriptor の下にある Pipeline Manager を確認します。
  • Blueprint ID が入っていたら Detach を押して空にし、再度アップロードします（新しいアバターとしてアップロードされます）。
  • 「Attempted to load the data for an avatar we do not own」のように、自分のものではないアバターの ID だと表示されることもあります。対処は同じです。
  • 自分のアバターを更新したい場合は、SDK の Content Manager タブでそのアバターの ID を確かめ、Pipeline Manager で Attach して入れ直します。
  • 購入アバターに ID が残っていた場合や、Content Manager でアバターを削除したのに ID が残っている場合に起こります。
  • 注意: Blueprint ID は他人に知られると不正利用の恐れがあるため、ID が写ったスクリーンショットを SNS に載せないでください。

詳しく
  • Build & Test（ローカルテスト）: 自分の PC の VRChat でだけ確認できる機能です。アップロードはされません。テストしたアバターは、アバターのメニューの SDK Test Avatars の欄に出ます。
  • Build & Publish: サーバーにアップロードします。
  • ローカルテストは改変の確認に便利なので、アップロード前の動作チェックに活用できます。

ツールをインポートしたのにメニューに出てこない

Unity Discord より

コンパイルエラーがあるとエディタ拡張のメニューが表示されません。Console のエラーを確認し、Reimport や Unity の再起動、必要な依存パッケージの導入を試します。

詳しく
  • Console にエラーが出ていると、他のスクリプトも含めてエディタ拡張が読み込まれません。エラー内容を確認します。
  • Reimport（対象フォルダ右クリック）や Unity の再起動で直ることがあります。
  • 新規プロジェクトでは動くなら、既存プロジェクト内の別ツールとの競合や古いバージョンの残骸が原因のことがあります。
  • 依存パッケージが 2 つ必要なツール（当時の UniVRM 0.8x 系など）は、片方の入れ忘れでもメニューが出ません。
  • Unity のバージョンがツールの対応範囲外でないかも確認します（当時は Unity 2018 → 2019 に変えたら解決した例があります）。

アバターを軽くするには（描画負荷とファイルサイズ）

BlenderUnityVRChat軽量化 Discord より

描画負荷はメッシュ数・マテリアル数・ポリゴン数・揺れもの数、ファイルサイズはテクスチャ解像度とシェイプキーが主に効きます。現行は Avatar Optimizer（AAO）で非破壊に軽量化するのが手軽です。

詳しく

効果の大きい順の目安

  1. 着替え（衣装）を減らす: 1 アバター 1 衣装にするだけでもかなり軽くなります。
  2. 見えない部分を消す: 衣装で隠れる素体メッシュや使わない小物を削除します。
  3. テクスチャ解像度を下げる: ダウンロードサイズに最も影響します（例: 2048 → 1024。Unity のテクスチャ Import 設定の Max Size で変更可能）。
  4. 揺れもの（PhysBone）を減らす・まとめる: 非表示部分の揺れものは消します（PhysBone のまとめ方）。
  5. メッシュを結合する: Skinned Mesh 数を減らします。
  6. マテリアルを減らす: テクスチャを 1 枚にまとめる（アトラス化）のは発展編です。

現行のおすすめ

  • Avatar Optimizer（AAO） の AAO Trace And Optimize をアバターのルートに付けると（Add Component > Avatar Optimizer > AAO Trace And Optimize）、アップロード時に未使用要素の削除やメッシュ結合などを自動で行います（元データは変更しません）。
  • AAO Merge Skinned Mesh で複数メッシュを結合でき、シェイプキーやアニメーションの参照も維持されます。

当時の手法

  • Blender で Ctrl+J でメッシュ結合、Unity のアセット MeshBaker でメッシュ・テクスチャを焼き込む方法が使われていました（MeshBaker）。
  • 結合前に各メッシュの UV マップ名を揃え、Ctrl+A → 全トランスフォームを適用しておかないと、UV が壊れたりサイズが変わったりします。
  • MeshBaker で 1 メッシュ 1 マテリアルにしても必ず軽くなるとは限らず、シェイプキーが混ざるデメリットもあります。

MeshBaker でメッシュを 1 つにまとめる（当時の手順）

Unity軽量化リギング Discord より

有料アセット MeshBaker でメッシュとテクスチャを結合する手順です。VRChat では現在 Avatar Optimizer（AAO）で同様のことを非破壊にできるため、新規には AAO をおすすめします。

詳しく

当時（Unity 2019 / SDK3 初期）の手順です。現在の VRChat 向けには Avatar Optimizer の Merge Skinned Mesh / Trace And Optimize を使う方が安全で手軽です。

  1. Texture and MeshBaker のオブジェクトを作成し、TextureBaker の Open Tools For Adding Objects を開きます。
  2. Exclude meshes with out-of-bounds UVs のチェックを外し、アバターを選択して Add Selected Meshes To Target を押します。顔（Body）メッシュは焼き込み対象から外します（表情用シェイプキーが多く、ファイルサイズが極端に増えるため）。
  3. Objects To Be Combined を確認し、Material Bake Options を設定して Create Empty Assets For Combined Material（保存先は Assets 以下）→ Bake Materials Into Combined Material。
  4. 子の MeshBaker オブジェクトで Output を Bake Into Prefab にし、Create Empty Prefab → Bake。
  5. できた Prefab を Hierarchy に置き、Unpack Prefab Completely して、結合メッシュをアバター直下に移し Root Bone を設定します。
  6. シェイプキー名の末尾に衝突回避用の番号が付く場合は、MeshBaker の設定で付けないようにします（付くと表情アニメーションが動きません）。

注意

  • 焼き込み前の元メッシュは、VRChat では 非アクティブでもアップロードされる ので、アバターの外に出すか削除します（VRM 出力では非表示なら出力されません）。
  • 表情が動かなくなったら MeshBaker 後に表情が動かない を参照してください。

メッシュを結合したら表情（シェイプキー）がアップロード後に動かない

Unity表情リギング軽量化 Discord より

表情アニメーションは「メッシュ名/シェイプキー名」のパスでシェイプキーを動かすため、結合後のメッシュ名やシェイプキー名が変わると動きません。結合後のメッシュ名を元の顔メッシュ名（大文字小文字も一致）にし、Avatar Descriptor の参照も結合後のメッシュにします。

詳しく
  • 原因: アニメーションは Body のような メッシュのパス + シェイプキー名 を参照します。結合でメッシュ名が変わったり、シェイプキー名の末尾に番号が付いたりすると参照が切れます。
  • 対処
    1. 結合（焼き込み）後のメッシュの名前を、元の顔メッシュと同じ名前にします（Body と body のような大文字小文字も合わせます）。
    2. VRC Avatar Descriptor の Lip Sync / Eye Look などで指定する顔メッシュは 結合後のメッシュ にします。
    3. 焼き込み前のメッシュはアバター外へ退避します。
  • Unity 上ではシェイプキーが動くのに VRChat やエミュレーターで動かない場合は、この参照切れを疑います。
  • AAO の Merge Skinned Mesh はこの参照を自動で付け替えるので、現行ではこちらを使うと起こりにくくなります。

衣装を着せ替えたあと、不要になったボーンは消した方がよいですか？

BlenderUnityリギング衣装 Discord より

基本的には消した方が軽くなります。ただし Humanoid のボーンは消さず、Blender ではウェイトが乗っていないことを確認してから消します。

詳しく
  • 消してよい: 元衣装のスカートボーンなど、使わなくなった補助ボーン。
  • 消してはいけない: Hips、手足など Humanoid に関係するボーン。
  • Blender で消す前に、メッシュの頂点グループにそのボーン名が使われていないか確認します（使われていると、その部分が動かなくなります）。
  • Unity 上でボーンを消す場合はコンポーネントやアニメーションの参照にも注意します。現行では Avatar Optimizer がアップロード時に未使用ボーンを自動で削除できます。
  • VRM の場合は、ボーンを削除すると「設計図にあるボーンがない」とエラーになるので、正規化前に無効化（非アクティブ）にしておくと正規化時に消えます。

Blender はどのバージョンを使えばよいですか？

Blender Discord より

使いたいアドオンが対応している範囲で、新しめの安定版（LTS など）を使うのがおすすめです。新しいバージョンではウェイト転送やシュリンクラップの選択肢が増えています。

詳しく
  • 基本方針: 使うアドオンの対応バージョン を確認し、その範囲で新しめの安定版を選びます。本サイトは Blender 4.5 を前提にしています。
  • 古い記事（Blender 2.8〜3.x）とはメニュー名や位置が変わっていることがあります。手順どおりに見つからない場合はバージョン差を疑ってください。
  • データ転送モディファイアーや、シュリンクラップの「ターゲットの法線で投影」「スナップモード」などは 2.8 系の時点で使えます。古い記事でこれらが無い前提の手順は、今は別の方法の方がきれいに仕上がることがあります。
  • 複数バージョンを並行してインストールできます（設定は別々に保存されます）。
  • Steam 版は自動更新で見た目が大きく変わるバージョンに上がることがあり、アドオンが動かなくなる場合があります。公式サイト版の方がバージョン固定しやすいです。
  • Blender 4.2 以降、アドオンは「エクステンション」として Extensions プラットフォームから入れる形に変わりました。古いアドオンは手動インストールが必要な場合があります。

ボーン（つま先など）が勝手に曲がっている／編集モードに入ると直る

Blenderリギング Discord より

ポーズモードでボーンが回転したままになっています。ポーズモードで該当ボーンを選び Alt+R（回転のリセット）、全体なら全選択して Alt+G / Alt+R / Alt+S でポーズをクリアします。

詳しく
  • ポーズモードでの変形は、編集モードに入っている間は表示されません。そのため「編集モードにすると普通に戻る」ように見えます。
  • 対処
    1. アーマチュアを選択してポーズモードにします。
    2. 曲がっているボーンを選び Alt+R で回転をリセットします。
    3. まとめて戻すなら A で全選択 → Alt+G、Alt+R、Alt+S（またはヘッダーの ポーズ > トランスフォームをクリア の中の、すべてをクリアする項目）。
  • ポーズモードで動きを確認したあと、戻し忘れたままウェイト転送などをするとずれる原因になります。作業前に必ずポーズをクリアしましょう。

Basis を編集したのにシェイプキーを 1 にすると元の形に戻る／変形が加算される

Blenderリギング Discord より

各シェイプキーは編集前の Basis との差分で形を持っているため、後から Basis だけを動かすとずれます。編集モードで動かした頂点を選び「シェイプに反映（Propagate to Shapes）」を使うか、シェイプキーで変形を作るのが安全です。

詳しく
  • どのシェイプキーを編集しているか確認: 編集モードの変更は、選択中（アクティブ）のシェイプキーに入ります。Basis 以外が選ばれていると、オブジェクトモードに戻ったときに元の形に見えます。
  • Basis の変更を他のシェイプキーにも反映する: 編集モードで Basis を選んで頂点を動かしたあと、動かした頂点を選択して 頂点 > シェイプに反映（Propagate to Shapes） を実行します。
  • 最初からやり直せるなら: Basis は直接いじらず、新しいシェイプキーで変形を作る方が安全です。首など体の形を変える場合も、まずシェイプキーで作ります。
  • 当時（2.9 頃）にあった「Basis に適用」系のメニューは 3.1 で見当たらなくなったという報告があります。Blender 4.5 のメニュー構成は実機で確認してください。
  • 一度ずれてしまった後の修正は難しく、作り直した方が早いこともあります。

  • Solver Frequency は VRChat 側の計算レートと合わないとローカルと動きが変わることがあります（当時は 90 の倍数がよいとされていました）。
  • Edit Cloth Constraints を押しても頂点が表示されない: Scene ビューの Gizmos が OFF になっていないか確認し、それでも出ない場合は Window > Layouts から任意のレイアウトを選び直すと直ることがあります。
  • 「Cloth を付けるには Armature モディファイアーを消す必要がある」というのは古い情報です。

PhysBone の Root Transform・Endpoint Position・Multi Child Type の考え方

UnityPhysBoneリギング Discord より

PhysBone は Root Transform に指定したボーンの子から揺れます。Unity のボーンは点なので、子のない単一ボーンは向きが決まらず揺れません（Endpoint Position で補います）。子が複数ある場合の根元の傾き方は Multi Child Type で決まります。

詳しく
  • Root Transform: ここに指定したボーンより下が揺れます。空欄にすると、コンポーネントを付けたオブジェクト自身がルートになります。
  • ボーンは点: Unity のボーンには長さがなく、次の点（子ボーンや _end）との位置関係で向きが決まります。
    • 子のない単一ボーンに PhysBone を付けても揺れません。
    • リーフボーン（〜_end）があると、その手前のボーンが揺れるようになります。
    • リーフボーンがない場合は Endpoint Position で末端の点を仮想的に追加します（単一ボーンにも長さを与えるイメージ）。
  • Multi Child Type: ルートの直下に子が複数ある場合、どの子に合わせてルートを傾けるか決められないため、既定（Ignore）ではルートは固定されます。First（最初の子に従う）や Average（平均）に変えられます。毛先が枝分かれしているボーンなどで検討します。
  • 作者の Root 指定ミスに注意: DynamicBone の感覚で Root を指定していて、本来揺れるべき根元が揺れない（または逆）アバターもあります。根元のボーンにウェイトが乗っているかで判断できます。
  • ボーン構造を変えるのが面倒なときは、角度制限（Limit）のカーブで根元だけ角度 0 にして固定する方法もあります。
